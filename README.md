
# Post-Quantum TLS 1.3 and QUIC Handshakes under Constrained Networks: Combining ML-DSA with ML-KEM and HQC

> **David Rive Tolokoum**, **Yves Bruno MBEZOA**, **Hervé Talé Kalachi**  

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
[![Docker](https://img.shields.io/badge/Docker-Containers-blue.svg)](0-docker/)
[![OpenSSL / OQS](https://img.shields.io/badge/Cryptography-liboqs%20%2F%20oqsprovider-green.svg)](https://github.com/open-quantum-safe/)

---

This repository provides an automated experimental testbed to evaluate and
compare the performance of **TLS 1.3 (over TCP)** and **QUIC (over UDP)**
when integrated with post-quantum cryptography.

The benchmark covers NIST-standardized lattice-based algorithms
(**ML-KEM** / FIPS 203 and **ML-DSA** / FIPS 204) alongside the code-based
**HQC** key encapsulation mechanism, evaluated across three NIST security
levels (L1, L3, L5), classical/hybrid/pure-PQC key exchange configurations,
and five network conditions — an ideal baseline, two static-impairment
profiles calibrated from real mobile network measurements, and two
Gilbert-Elliott burst-loss models (stable / unstable).

## Prerequisites

- **Docker** (with cgroup CPU/memory accounting enabled)
- **[Pumba](https://github.com/alexei-led/pumba)**, for `netem`/Gilbert-Elliott network impairment (`stable`, `unstable`, and `simple` profiles)
- **tshark** — `sudo apt-get install -y tshark` (used by `parse_traffic_size.py` and `analyze_traffic_size.sh`)
- **Python 3.9+** with `pandas`, `numpy`, `matplotlib`
- A pre-built OQS-enabled test image (`uma-tls-quic-pq-34`, or your own tag) — built from `0-docker/Dockerfile`

```bash
pip install pandas numpy matplotlib
docker build -t uma-tls-quic-pq-34 -f 0-docker/Dockerfile 0-docker/
```

> **Run everything from the repository root.** The analysis and plotting
> scripts resolve `captures/`, `results_traffic_size/`, and `plots_global/`
> as paths relative to the current working directory, not relative to the
> script's own location. Always invoke them as
> `python3 scripts_plotting/<script>.py` from the repo root — not from
> inside `scripts_plotting/`.

## Quick start

### 1. Preflight check

```bash
./Launcher_preflight_check.sh both
```

### 2. Main benchmarking harness

```bash
./Launcher_pq_mldsa_mlkem_hqc.sh <kem_family> <protocol> <auth_mode> <capture_mode> <network_profile> [loss_pct] [delay_ms]
```

| Parameter | Values | Notes |
|---|---|---|
| `<kem_family>` | `mlkem`, `hqc`, `both` | `both` runs classical + hybrid + pure-PQC for every KEM family |
| `<protocol>` | `tls`, `quic` | |
| `<auth_mode>` | `single`, `mutual` | QUIC currently only has `single`-auth captures |
| `<capture_mode>` | `nocapture`, `captureKey`, `capture` | `nocapture` is required for the full 500-execution statistical sweep; the capture modes force a single execution and are meant for `captures/traffic_size/` / packet-level inspection |
| `<network_profile>` | `none`, `simple`, `stable`, `unstable` | `none` = ideal; `simple` = static loss/delay (needs the two optional args); `stable`/`unstable` = Gilbert-Elliott burst-loss models |
| `[loss_pct]`, `[delay_ms]` | e.g. `0.3`, `30.02` | Only used when `<network_profile>` is `simple` |

```bash
# Ideal network, TLS 1.3, single-auth, full statistical sweep (ML-KEM + HQC)
./Launcher_pq_mldsa_mlkem_hqc.sh both tls single nocapture none

# Moderate 4G profile (0.3% loss, 30.02ms delay), QUIC
./Launcher_pq_mldsa_mlkem_hqc.sh both quic single nocapture simple 0.3 30.02

# Gilbert-Elliott unstable profile, TLS mutual auth
./Launcher_pq_mldsa_mlkem_hqc.sh both tls mutual nocapture unstable
```

**Resuming an interrupted run.** The launcher is idempotent: before running
a given `(sig_alg, kem)` combination, it checks whether a row for that exact
combination already exists in the target scenario's
`resource_usage_*.csv`, and skips it if so. If a run is interrupted (e.g. a
transient Docker/Pumba network error), simply re-issue the **exact same
command** — already-completed combinations are skipped automatically and
execution resumes where it left off. No manual editing of the script is
needed.

### 3. Advanced test suite

```bash
./Launcher_advanced_tests.sh ideal        # concurrent-load + session-resumption, one scenario
./launchers/run_all_scenario_tests.sh ideal   # full campaign: sweep + advanced + validation
```

## Data pipeline: capture → analysis → figures

Each scenario directory (`captures/<protocol>/<auth_mode>/<scenario>/`) goes
through the same three stages:

### Stage 1 — Raw logs to CSV

```bash
python3 scripts_analysis/logs_to_csv.py captures/tls/single/none/handshake_logs
# or, recursively, for every scenario at once:
python3 scripts_analysis/logs_to_csv.py captures --all
```

### Stage 2 — Statistics and aggregation

```bash
python3 scripts_analysis/analyze_handshake_performance.py captures/tls/single/none
python3 scripts_analysis/Analyze_resource_usage.py --input-dir captures/
python3 scripts_analysis/parse_traffic_size.py --input-dir captures/traffic_size --out-dir results_traffic_size/
```

### Stage 3 — Figures

All figure scripts import `scripts_plotting/plot_style.py`, the shared
module defining the colorblind-safe palette (color = KEM family, never
reused for unrelated dimensions across figure types), typography, output
sizing, and the KEM-family classification/sorting/labeling helpers used
everywhere else in the pipeline.

| Script | Scope | Output |
|---|---|---|
| `plot_handshake_latency.py` | Per protocol × auth mode × scenario × security level | `captures/<protocol>/<auth_mode>/<scenario>/plots/handshake_*.pdf` |
| `plot_traffic_size.py` | Global (single auth only, all levels/protocols in one pair of figures) | `results_traffic_size/plots/traffic_size_{classical,pq}_sig.pdf` |
| `plot_resource_usage.py` | Per protocol × auth mode × scenario × security level, CPU and memory separately | `captures/<protocol>/<auth_mode>/<scenario>/plots/resource_{cpu,mem}_*.pdf` |
| `plot_global_kem_comparison.py` | Cross-level, ideal network only | `plots_global/kem_family_overhead_by_level.pdf` |
| `plot_global_sig_comparison.py` | Cross-level, ideal network only, paired by KEM | `plots_global/sig_family_latency_delta_by_level.pdf` |
| `plot_global_network_sensitivity.py` | Cross-scenario, cross-level | `plots_global/network_sensitivity_by_level.pdf` |

```bash
# Per-scenario figures (loops over every protocol/auth_mode/scenario found under captures/)
python3 scripts_plotting/plot_handshake_latency.py
python3 scripts_plotting/plot_resource_usage.py

# Traffic size (reads results_traffic_size/traffic_size_summary.csv)
python3 scripts_plotting/plot_traffic_size.py

# Cross-scenario / cross-level synthesis figures
python3 scripts_plotting/plot_global_kem_comparison.py
python3 scripts_plotting/plot_global_sig_comparison.py
python3 scripts_plotting/plot_global_network_sensitivity.py
```

Every figure is written as both a vectorial PDF (`pdf.fonttype: 42`, for
direct submission) and a 300 dpi PNG (for quick preview).

## Network profile reference

| Directory name | Label used in figures | Description |
|---|---|---|
| `none` | Ideal | No delay, no loss |
| `simple_loss0.3_delay30.02ms` | Moderate (4G) | Static impairment calibrated on MTN 4G measurements |
| `simple_loss0.2_delay65.15ms` | Degraded (4G) | Static impairment calibrated on Orange 4G measurements |
| `stable` | GE-Stable | Gilbert-Elliott burst-loss model, mild parameters |
| `unstable` | GE-Unstable | Gilbert-Elliott burst-loss model, severe parameters |

Delay is applied bidirectionally on both container interfaces; loss is
asymmetric (server-to-client only). Raw calibration captures are kept under
`sessions/`.

## Data integrity notes

A few pipeline quirks are worth knowing if you extend this benchmark:

- **`Launcher_pq_mldsa_mlkem_hqc.sh` appends to `resource_usage_*.csv`, it never overwrites it.** Re-running the launcher on a scenario that already has a complete CSV will add duplicate rows for the combinations it re-executes. The idempotent skip check (see Quick start) prevents this for interrupted-run resumes, but a fully intentional re-run of an already-complete scenario should still start from a clean file (move the old one aside first).
- **Decimal-comma corruption**: under a French/EU locale, the shell-side
  `awk printf "%.3f"` formatting in the resource-usage collection can emit
  a comma instead of a dot in `cpu_usec_per_handshake`, splitting that
  field into two CSV columns. This is mechanical and fully reversible;
  fix it with the CSV repair utility before running any analysis on an
  affected file.
- Every plotting script validates its input structure (expected columns,
  expected row counts, KEM-name-to-family classification) and prints an
  explicit `[ATTENTION]` rather than silently producing a biased or
  incomplete figure. Treat any such message as blocking, not informational.
